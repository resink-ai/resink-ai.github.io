# Agent Engineering OKR — 2026-05-30

## Context

Bundle C closes the 17-task bottom-up flow plan from [ADR-2026-05-09-001](../../../../board/decisions/2026-05-09-001-org-os-bottom-up-flow.md). Bundle A (T1–T5) landed 2026-05-10; Bundle B (T6–T12) landed clean at 2026-05-23 with the three-loop slip pattern broken under ADR-2026-05-16-002's hard floor. The remaining five tasks — T13–T17 — are this loop's primary work, plus the DISPATCH.md `--bare` addendum that was brief-deferred from 2026-05-23.

Three things make Bundle C structurally different from Bundle B:

1. **Lower volume.** Five tasks vs Bundle B's seven; no ADR-002-class hard floor is needed because the bandwidth pressure is lower and there is no rolling slip history to defend against.
2. **Less ritual-edit-heavy.** T13–T15 are role-file edits (existing files at `org-os/roles/{EM,CEO,IC}.md` get the plan's per-section replacements + frontmatter added); T16 is one README edit; T17 is wholly-new walk authoring. The only Bundle C task touching a ritual file is implicit (the README references rituals; the rituals themselves don't move).
3. **No same-file merge collision risk with the board this loop.** Board's [ADR-2026-05-23-001](../../../../board/decisions/2026-05-23-001-conventions-enum-extension.md) extension edits `org-os/conventions.md` (type enum + additional-fields table). AE edits no conventions content. The role files reference the enum types `playbook` and `runbook` (for the rituals-owned tables); whether those types are ratified by the time AE writes is a sequencing question, not a merge-conflict question — they are different lines in different files.

The DISPATCH.md `--bare` addendum closes the deviation that resink-core's orchestrator has been working around for two loops (2026-05-16 introduced the non-`--bare` invocation form; 2026-05-23 deferred the addendum). Sized S; lands in the same loop as Bundle C with zero strain on the role/README/walks bandwidth.

## Decisions made this loop (recorded here so the board can sequence against them)

- **No hard floor framing.** Bundle C runs as a normal-cadence loop, not under ADR-2026-05-16-002 succession. AE remains disciplined about not taking codegen pattern expansion or other floor pulls (named explicitly in Out of scope), but the discipline is informal — no ADR ratifies a Bundle C hard floor and none is needed.
- **Worked-flow walks placement: `org-os/playbooks/walks/<slug>.md`.** Three files, one per walk. Rationale: walks are step-by-step "how this flows end-to-end" docs that are closer to playbooks than to rituals (each ritual file is single-step; walks span 4–8 steps across files). Appending three walks to `org-os/README.md` would push the README past its job (it's the index, not the worked-example tutorial). A top-level new `org-os/walks/` directory would create a fourth org-os taxonomy without an ADR. Nesting under `playbooks/walks/` keeps the directory shape unchanged at the top level, preserves discoverability for anyone reading `playbooks/`, and lets the README cite a single sub-tree from the existing playbooks row. If the board's ADR-2026-05-23-001 extension ratifies `type: playbook` by the time the walks are written, each walk file uses `type: playbook` with `invocation_trigger: "reading-time, when orienting on the flow"`; if not, the walks ship without frontmatter (they are reference docs inside `org-os/` like the rituals, which also carry no frontmatter — see Risks).
- **Role-file frontmatter shape.** The existing `org-os/roles/{EM,CEO,IC}.md` files carry no frontmatter today (they are reference docs analogous to ritual files). The brief's KR shapes name `status: active` for each, implying frontmatter must land alongside the body edits. AE adds frontmatter with `type: role` if board's enum extension ratifies that type by mid-loop; otherwise AE files with no frontmatter and a one-line note that frontmatter follows once the enum admits `role`. Coordination point with board on 2026-06-02 (see Cross-team asks). The plan's verify checklists for T13–T15 are silent on frontmatter, so this is brief-additive: AE follows the brief.
- **No `org-os/rituals/` re-edits this loop.** Bundle B shipped all seven ritual edits clean; Bundle C does not touch them again. The README's rituals table refresh in T16 references the existing `team-intake.md` row; the row itself was added by the plan's Step 2 diff in T16, which AE applies verbatim. The `executive-loop.md`, `ceo-brief.md`, `team-planning.md`, `exec-summary.md`, `ceo-consolidation.md`, `retro.md` files are read-only to AE this loop.
- **Marketplace edit is bounded to one file.** The DISPATCH.md `--bare` addendum is a single new section append to `repos/resink-ai/resink-marketplace/plugins/nanofab/skills/codegen-scd2-node/DISPATCH.md`. No edits to `SKILL.md`, `SMOKE.md`, `templates/`, or any other marketplace file. The `bash repos/resink-ai/resink-marketplace/tests/run-all.sh` run is a regression check, not a deliverable; the addendum is reference text and the test surface validates manifest/hook shape, not DISPATCH content.
