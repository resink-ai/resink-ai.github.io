## Objectives

### O1: Ship v1 of the `resink` power-user CLI

source: ceo-brief

Why it matters: First user-facing surface in the company. The product UX spec catalogs four surfaces; the CLI is the smallest scope that gives a real user experience today, without requiring a backend API or web stack. Read-only on the local filesystem makes v1 viable WITHOUT any new infrastructure — just a Rust binary that pretty-prints what's already on disk. Operators interacting with the supervisor's output (after `make mvp-loop` or after a home-cluster deploy where the trace was kubectl-cp'd locally) get a navigable surface. Future loops add: write commands (retrain triggers, hot-swap rollback); remote commands (OAuth + backend API); Homebrew tap.

**Key results**

- KR1.1: New Cargo workspace member at `repos/resink-ai/resink-core/crates/resink-cli/` with `Cargo.toml`, `src/main.rs`, `src/commands/` (one module per subcommand). Crate name `resink-cli`; binary name `resink` (via `[[bin]] name = "resink"`); package version `0.1.0`. Dependencies: `clap` 4.x (workspace), `serde_json` (workspace), `serde_yaml` (workspace), `arrow` 53 (workspace) for parquet reading, `parquet` 53 (workspace), and `anyhow` for error handling (new dependency; pin to 1.x).
- KR1.2: 5 subcommands implemented:
  - `resink workspace status` — prints the workspace path being used, the parent commit SHA (`git rev-parse HEAD` inside the workspace's enclosing repo), and a clean/dirty indicator.
  - `resink verdict latest` — reads `workspace/verdict.json`; pretty-prints with TTY colorization (green for `overall_pass: true`, red for false); shows engine version, per-dim pass/fail, mismatch counts.
  - `resink manifest get` — reads `workspace/manifest.yaml`; pretty-prints (just `cat`-equivalent with optional `--json` flag for `yq`-friendly output).
  - `resink table head <dim> [--limit N]` — reads `workspace/<dim>_output.parquet` via `parquet` crate; prints first N rows (default 10) in a tabular format. Supported dims: `dim_user`, `dim_account` (v1).
  - `resink trace tail [--lines N]` — reads `workspace/trace.jsonl`; prints last N lines (default 20) pretty-formatted (one JSON object per line, indented).
- KR1.3: `resink --help` and per-subcommand `--help` produce useful text. The top-level help names all 5 subcommands + the global `--workspace <path>` flag.
- KR1.4: `--workspace <path>` global flag for explicit workspace location. Defaults: (a) `$RESINK_WORKSPACE` env var if set; (b) else walk up from cwd looking for `synthetic_tenants/*/workspace/` directory; (c) else error with a useful hint.
- KR1.5: Build green: `cargo build --release -p resink-cli` exits 0. Binary at `target/release/resink`. Unit tests: at least one per subcommand testing argument parsing + file-reading; `cargo test -p resink-cli` exits 0.

Cross-link from the existing "Common commands" section + chart README (TBD if relevant).

## Risks

- **Workspace resolution heuristic.** The `--workspace` walk-up heuristic (find `synthetic_tenants/*/workspace/`) may be confusing when the operator's cwd is unrelated to the resink-core checkout (e.g., they're in `~/` or in the home-cluster repo). Mitigation: KR1.4 names `$RESINK_WORKSPACE` env var as the primary override; the error message when no workspace can be found is explicit and names both fallbacks.
- **Parquet rendering quality.** Pretty-printing a parquet table with `arrow` + `parquet` is straightforward but the formatting (column widths, type display, null rendering) is subjective. v1 uses `arrow` 53's built-in `prettyprint` for the table; future loops can swap for a custom formatter.
- **Cross-arch consistency.** The CLI is Rust; cross-compiles trivially via cargo. v1 distribution is `cargo install` from source, so users build for their platform. Future Homebrew distribution requires pre-built binaries for macOS arm64 + amd64 + linux amd64.
- **Naming collision with `resinkit` Python packages.** The user's other workspace under `resinkit/` has Python worker services + SDKs. The CLI name `resink` is distinct (5 chars vs 7) but operators may type `resinkit` by muscle memory. Mild risk; mitigation is the help-text disambiguation.
- **First content push to the new remote.** The resink-core submodule was bootstrapped last loop with the subtree-split history. This loop's commit is the first development push. No CI/CD on the remote yet (deferred per 2026-05-12-1254 retro P2); if a push goes wrong, recovery is force-push (acceptable for a freshly-bootstrapped repo with one contributor).
- **Versioning.** The supervisor crate is at `0.3.0`; this CLI starts at `0.1.0`. Independent versioning is expected (CLI evolves independently of the runtime). Documented in the user-guide section.
