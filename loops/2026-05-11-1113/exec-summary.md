## Cross-cutting blockers

- **Sim-farm diff engine hard-codes `user_id` as join column and `(email, country, valid_to, is_current)` as payload columns.** Surfaced during resink-core's Wave-2 build of the `dim_account` dim. Resink-core resolved this loop's instance with an isomorphic compromise: dim_account's parquet column shape is identical to dim_user's (account_id literals in the `user_id` column, account_type|status compound in the `country` column). SCD2 semantics and 4-shard partitioning are exercised correctly; only the column-name *semantics* are renamed. **This blocks a third or differently-shaped dim from being added** — every new dim has to be renamed-into-the-`user_id`-shape until the engine becomes schema-aware. Sim-farm flagged for retro: likely shape is a `--schema <path>` flag per pair (or a sibling schema-JSON next to each fixture) so the engine reads the canonical PK + payload column names rather than hard-coding. **Highest-priority retro item.**
- **Workspace promotion to a real git submodule deferred for the second consecutive loop.** Recorded blocker: the `resink-ai/resink-core` GitHub remote doesn't exist yet. Three crates plus a Python orchestrator plus a fixture plus the sim-farm subtree plus the deploy charts now live in-tree; further loops of drift compound the eventual cross-repo migration cost. **Board action needed**: approve or create the `resink-ai/resink-core.git` GitHub remote so resink-core can complete promotion in loop 2026-05-11-1302.
- **DevOps minikube smoke deferred.** No docker/minikube on the IC's developer machine. The smoke target is shipped + lint-clean + dry-run-clean, but the live deployment check didn't run. Carrying to 2026-05-30 — board action either (a) approve docker/minikube install, (b) pivot the smoke to Docker-Desktop-on-Mac (which is already available on developer laptops), or (c) provision a shared minikube target.
- **Runtime `BLOCKED` observable doesn't exist as a distinct supervisor surface.** SRE's runbook documents this as `TODO: verify against impl` with forward-pointer to post-`dlopen` restoration. The MVP supervisor exits 1 on failure with a stderr line — sufficient for the MVP but inadequate for the production hot-swap state machine. Ties to ADR-001's restoration plan: the supervisor swap to `libloading::Library` at loop 2026-05-11-1631 is the natural place to add the BLOCKED state observable.
- **DevOps surfaced 5 supervisor-side hand-off items for post-dlopen work.** No `/healthz` endpoint, no SIGTERM drain logic, no env-var-driven config, no long-running HTTP, no Dockerfile-owned-by-supervisor. The chart works around these with `healthz.enabled: false` and `restartPolicy: Never` — adequate for the not-long-running MVP shape, but each gap is a post-`dlopen` work item for resink-core. Cumulatively this is part of the "Option A → dlopen" restoration burden.
- **`type: runbook` not in the conventions enum.** SRE filed the runbook as `type: runbook` (a charter-grounded SRE-local extension) with workaround documented inline. Sister to ADR-2026-05-10-004 (contract type addition); flagged for retro as a small follow-up ADR to add `runbook` to the conventions enum.
