## Surprises

- **(NEGATIVE — found-while-documenting) The `CLAUDE_SKIP_DISPATCH=1` env var named in the original build prompt does not actually exist.** Investigation during `docs/user-guide.md` § Environment Variables authoring: the Makefile's `ORCH_FLAGS` defaults to `--skip-dispatch` (a **CLI flag** consumed by `training/orchestrator/src/orchestrator/__main__.py`), and the live env var is `CLAUDE_DISPATCH=1` with **inverse semantics** — `CLAUDE_DISPATCH=1` *enables* LLM dispatch by causing the Makefile to drop `--skip-dispatch` from `ORCH_FLAGS`. The negation lives entirely on the CLI flag, not on an env var. The user-guide documents the real env var (`CLAUDE_DISPATCH`) and explicitly flags the non-existence of `CLAUDE_SKIP_DISPATCH` so future agents reading the docs do not chase a phantom env var. **Significance:** small, but representative — the docs authoring caught one factual claim that no one would have noticed until someone tried to use the phantom var.
- **(NEGATIVE — found-while-documenting, second item) `repos/resink-ai/resink-core/synthetic_tenants/closed_loop_v0/Makefile`'s `clean` recipe is the canonical artifact list, not the README.** Initially attempted to enumerate `make clean` artifacts from secondary descriptions; ended up reading the Makefile target directly to ensure the doc matched on-disk reality. This is the lesson the `rit-docs-init` SKILL.md red-flag list anticipates ("hallucinated architecture") — the temptation to write what the runtime *should* clean rather than what the recipe actually removes. The user-guide ended up citing the Makefile recipe lines directly.
- **(POSITIVE) The docs surface partially substitutes for outside-the-tree observability of resink-core that workspace promotion would otherwise provide.** Combined with the board's companion HTML capabilities report at `board/reports/2026-05-30-resink-core-capabilities.html` (18KB, board-authored on top of our docs surface — **cross-loop closure**, not our KR), resink-core is now genuinely orientable from outside the immediate file tree: any IC opening the repo can find the right pointer to the right file within a minute, per the [`ORG.md`](../../../../ORG.md) vision. The CEO brief explicitly named this partial-substitution; the docs delivered it. **Caveat (carried to § Asks):** this does NOT dissolve the workspace promotion debt; the third-consecutive defer still carries forward to 2026-06-06 as a fourth-loop flag for retro.
- **(POSITIVE) The four `docs/` bodies came in well above the ≥200-words-per-section floor.** Targets were ≥200 words per section; delivered 1747 (architecture, 5 sections; ~349 words/section), 1261 (concepts, 14 terms), 1240 (user-guide, 5 sections; ~248 words/section), 745 (module-catalog, 7 entries; ~106 words/entry — under the per-section minimum, but each entry is the four-element shape per KR1.5 and the per-entry bar is "path + purpose + dependents + entry point", not a 200-word floor; the overall body is ≥200 words across the file).
